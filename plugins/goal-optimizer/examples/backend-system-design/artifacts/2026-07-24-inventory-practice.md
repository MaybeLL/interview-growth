# 练习逐字稿 — 库存扣减接口(变式题)

日期:2026-07-24
形式:练习题,允许提示。这是一道"变式题":把学过的幂等从支付迁移到库存场景。

---

题目:设计一个"秒杀下单扣库存"的接口。用户抢购,点击下单后扣减商品库存并生成订单。请说明你的设计。

候选人:好,秒杀下单。请求进来,我先校验库存够不够,够的话就扣减库存 `stock = stock - 1`,然后创建订单。为了防止超卖,我扣库存的时候用 `update ... set stock = stock - 1 where id = ? and stock > 0`,靠这个条件更新保证不会扣成负数。

面试官(练习助手):超卖这块处理得对。那如果用户点了下单按钮之后没反应,他又点了一次,会发生什么?

候选人:那……第二次请求进来,库存还够的话,就又扣了一次,又生成了一个订单。用户其实只想买一件,结果下了两单、扣了两件库存。

面试官(练习助手):对。这个问题你在之前哪道题里见过类似的?

候选人:嗯…………(停顿)哦!这个其实就是重复提交,跟支付那道题的重复扣款是一类问题。应该用幂等。我给这个下单请求加一个幂等键,同一次点击意图用同一个键,第二次重复请求进来发现键已经处理过,就直接返回第一次的订单,不再扣库存。

面试官(练习助手):不错,提示一下之后你把它对应上了。那你这个幂等键具体怎么跟秒杀场景结合?键存哪、并发怎么保证?

候选人:键的话……我存数据库,给它加唯一索引。并发的话,呃,我想想——如果两个相同键的请求几乎同时进来,可能两个都查到"没处理过",然后都去扣库存了。所以光查一下不太够。可能得靠唯一索引插入,谁先插进去谁处理,另一个插入失败就返回。不过这块我刚才第一反应没想到,是你提醒并发我才补上的。

面试官(练习助手):可以。今天先到这。
