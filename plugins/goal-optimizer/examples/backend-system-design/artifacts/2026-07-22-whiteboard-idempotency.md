# 白板讲解逐字稿 — 概念:幂等

形式:对着白板讲清楚"幂等"这个概念,无时间限制,无提示,无参考资料

---

候选人:我讲一下幂等。幂等这个词最简单的定义就是:一个操作执行一次,和执行很多次,对系统状态产生的效果是一样的。

比如 HTTP 里,GET 天然幂等,查一次查十次数据库状态不变;PUT 用一个完整对象覆盖资源,也是幂等的,你 PUT 十次结果都一样;但 POST 通常不幂等,因为它一般表示"新建",连点两次就建两条。

在业务系统里我们关心的是"写操作的幂等",典型就是扣款、下单、发消息这种。做法核心是幂等键:

第一,调用方为"一个业务意图"生成一个稳定的键。注意是一个业务意图对应一个键,而不是一次网络请求一个键——重试是同一个意图,所以重试必须复用同一个键。

第二,服务端拿到键先查:这个键处理过没有?没处理过,就执行真正的业务逻辑,并且把"键 + 结果"原子地存下来;处理过,就直接把上次的结果回放给调用方,不再重复执行。

第三,存储上要保证"检查键"和"写业务结果"是原子的,否则并发下两个相同键的请求可能都通过了检查。常见做法是给键建唯一索引,靠数据库的唯一约束来兜底并发;插入冲突了就说明有人先处理了,转成读取已有结果返回。

我特别强调一下键的选择,这是最容易错的地方:键要绑定"业务意图"而不是"请求内容"。比如同一笔订单支付,重试时内容一样,键也一样,正确;但如果两笔是用户真的想付两次的钱,那是两个意图,必须是两个不同的键,不能因为金额收款方相同就被误判成重复。

这就是幂等的核心:同一意图重试用同键、不同意图用不同键,服务端靠"键+结果"的原子存储做去重和结果回放。
